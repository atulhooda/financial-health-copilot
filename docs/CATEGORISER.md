# Categoriser evaluation

Generated by `hisaab train-categoriser` (deterministic: same seed, same numbers). SPEC §5.4, D15.

Rules categorise every merchant in `config/merchants.yaml`. The LightGBM fallback (char 2-5-gram TF-IDF
on the payee + log amount + channel) handles the rest, mostly local merchants.

Training data: 9202 synthetic narrations over 12 classes (dining, education, entertainment, fuel, groceries, health, insurance, shopping, telecom, transport, travel, utilities).

| Holdout | Rows | Accuracy | Macro-F1 | Share below 0.5 confidence (→ `other`) |
|---|---|---|---|---|
| Unseen merchants (new names, familiar kind of shop, e.g. a new "… Medical") | 2300 | 99.7% | 0.996 | 0.1% |
| Unseen merchant *types* (a category word never seen in training) | 1032 | 25.6% | 0.202 | 30.3% |

Held-out type words: dining: "Chinese Corner", education: "Stationers", entertainment: "Club", fuel: "Petro Services", groceries: "Super Bazaar", health: "Eye Care", insurance: "Insurance Services", shopping: "Home Decor", telecom: "Net Services", transport: "Bike Rentals", travel: "Yatra Services", utilities: "Plumbing Services".

**Caveat.** Synthetic template narrations: accuracy is optimistic versus real bank data (SPEC D15). The first row mostly measures whether the model has learnt that
"Medical" means health. The second row is the honest one for a merchant it has never seen the like of:
those fall back to `other` or get a low-confidence guess, and the user can correct them
(`category_source = user`).
